Chapitre 3 : Sprint 1 – Authentification et Gestion des Utilisateurs
Introduction
Dans ce chapitre, nous présentons les démarches réalisées pour l’atteinte des objectifs de ce premier sprint, à savoir : la création de compte, l’authentification JWT, la réinitialisation du mot de passe, la gestion du profil utilisateur, la validation et le rejet des comptes, la désactivation/réactivation des comptes ainsi que la création de comptes chefs de projet. Nous commençons par les diagrammes UML, puis nous présentons les interfaces réalisées.

2.2.1. Créer un compte (Membre / Testeur / Développeur)
Cas d’utilisation : Créer un compte
Sommaire d’identification
Titre
Créer un compte
Description
Ce cas décrit le processus d’inscription d’un nouveau membre sur la plateforme de ticketing.
Acteurs
Membre, Testeur, Développeur
Description des enchaînements
Pré-condition
Disposer d’une adresse email valide et non encore utilisée sur la plateforme.
Post-condition
Le compte est créé avec le statut « en_attente » en attente de validation par un Admin.
Scénario nominal
1. L’utilisateur accède à la page d’inscription.
2. Le système affiche le formulaire d’inscription.
3. L’utilisateur saisit ses informations (nom, prénom, email, mot de passe, rôle).
4. La vue vérifie la validité des champs.
5. Le contrôleur transmet les données au modèle.
6. Le modèle vérifie l’unicité de l’email.
7. Le modèle crée le compte avec le statut « en_attente ».
8. Un email de confirmation est envoyé à l’utilisateur.
9. Un message de succès est affiché.
Enchânements alternatifs
E1 : Champs invalides → message d’erreur affiché, formulaire conservé.
E2 : Email déjà utilisé → message d’erreur indiquant que l’adresse est déjà associée à un compte.

2.2.2. S’authentifier
Cas d’utilisation : S’authentifier
Sommaire d’identification
Titre
S’authentifier
Description
Ce cas détaille la procédure d’authentification JWT des utilisateurs sur la plateforme.
Description des enchaînements
Acteurs
Membre, Admin, Chef de projet
Pré-condition
Disposer d’un compte actif sur la plateforme.
Post-condition
Un token JWT est généré et l’utilisateur est redirigé vers son tableau de bord selon son rôle.
Scénario nominal
1. L’utilisateur accède à la page d’authentification.
2. Le système affiche le formulaire de connexion.
3. L’utilisateur saisit son email et son mot de passe.
4. Le modèle vérifie les identifiants et le statut du compte.
5. Un token JWT est généré.
6. L’utilisateur est redirigé vers son tableau de bord selon son rôle.
Enchânements alternatifs
E1 : Identifiants incorrects → message d’erreur affiché.
E2 : Compte en attente ou rejeté → accès refusé avec message explicatif.
E3 : Compte désactivé → message d’erreur affiché.

2.2.3. Réinitialiser le mot de passe
Cas d’utilisation : Réinitialiser le mot de passe 
Sommaire d’identification
Titre
Réinitialiser le mot de passe
Description
Ce cas présente les étapes du processus permettant à un utilisateur de réinitialiser son mot de passe en cas d’oubli.
Acteurs
Membre, Testeur, Développeur, Admin, Chef de projet
Description des enchaînements
Pré-condition
L’utilisateur possède un compte actif avec une adresse email valide.
Post-condition
Le mot de passe est mis à jour avec succès et l’utilisateur est redirigé vers la page de connexion.
Scénario nominal
1. L’utilisateur clique sur « Mot de passe oublié ».
2. Le système affiche le formulaire de récupération.
3. L’utilisateur saisit son adresse email.
4. Le modèle vérifie l’email et génère un token SHA-256 valable 1h.
5. Un lien de réinitialisation est envoyé par email.
6. L’utilisateur saisit son nouveau mot de passe.
7. Le système met à jour le mot de passe et confirme le succès.
Enchânements alternatifs
E1 : Email inconnu → message d’erreur.
E2 : Token expiré → invitation à refaire la demande.
E3 : Mot de passe non conforme → message d’erreur explicatif.

Cas d’utilisation : Gérer son compte
Sommaire d’identification
Titre
Gérer son compte
Description
Ce cas illustre la manière dont un membre gère son profil en modifiant son email ou son mot de passe.

Membre
Description des enchaînements

L’utilisateur doit être authentifié.
Post-condition

Scénario nominal
1. L’utilisateur accède à sa page de profil.

4. Un message de succès est affiché.
Enchânements alternatifs
E1 : Email déjà utilisé → message d’erreur.
E2 : Ancien mot de passe incorrect → message d’erreur.

Les diagrammes de séquence permettent la modélisation dynamique d’un système en langage UML. Ils décrivent les interactions temporelles entre les différents composants (acteur, vue, contrôleur, modèle, système de mailing) pour réaliser un cas d’utilisation donné. Chaque flèche pleine représente un appel, et chaque flèche en pointillé représente un retour.

5. Revue du Sprint 1
Cette section présente les résultats obtenus lors du premier sprint, illustrés par les interfaces développées de l’application.
5.1. Interface d’Inscription
L’interface d’inscription permet au membre de saisir ses informations personnelles (nom, prénom, email, mot de passe et rôle). Une validation des champs est implémentée côté client et côté serveur pour garantir la qualité des données.
Figure 7 — Interface d’inscription
5.2. Interface d’Authentification
L’interface d’authentification permet à tous les utilisateurs de se connecter via leur email et mot de passe. En cas d’échec, un message d’erreur explicite est affiché.
Figure 8 — Interface d’authentification
5.3. Interface de Réinitialisation du Mot de Passe
L’interface de réinitialisation guide l’utilisateur à travers les étapes : saisie de l’email, réception du lien sécurisé et définition d’un nouveau mot de passe.
Figure 9 — Interface de réinitialisation du mot de passe
5.4. Interface de Gestion du Profil
L’interface de gestion du profil permet au membre de modifier son adresse email ou son mot de passe. La modification de l’email requiert la vérification du mot de passe actuel pour des raisons de sécurité.
Figure 10 — Interface de gestion du profil
5.5. Interface de Validation des Comptes
L’interface de validation permet à l’Admin de consulter la liste des comptes en attente et de valider ou rejeter chaque demande. Le membre reçoit une notification email selon la décision prise.
Figure 11 — Interface de validation des comptes
5.6. Interface de Gestion des Utilisateurs
L’interface de gestion des utilisateurs permet à l’Admin de consulter la liste complète des utilisateurs, de désactiver ou réactiver leurs comptes. Chaque action déclenche l’envoi d’un email de notification au membre concerné.
Figure 12 — Interface de gestion des utilisateurs
5.7. Interface de Création d’un Compte Chef de projet
L’interface de création de compte chef de projet est réservée à l’Admin. Elle permet de saisir les informations du chef de projet, générer automatiquement un mot de passe temporaire et l’envoyer par email.
Figure 13 — Interface de création d’un compte chef de projet
6. Rétrospective du Sprint 1
Cette section présente les réalisations du premier sprint. L’ensemble des objectifs ont été atteints avec la mise en œuvre complète de toutes les fonctionnalités planifiées : inscription avec validation par Admin, authentification JWT sécurisée, réinitialisation du mot de passe par email, gestion du profil (email et mot de passe), validation/rejet des comptes avec notification email, désactivation/réactivation avec notification email, et création de comptes chefs de projet avec mot de passe temporaire.
Conclusion
Ce premier sprint a permis de mettre en place les fondations sécurisées de la plateforme de ticketing : la gestion complète des utilisateurs et l’authentification JWT. Le prochain chapitre présentera le déroulement du deuxième sprint.
